# Mobile Flutter Bootstrap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bootstrap `apps/mobile` as a reproducible Flutter Android/iOS application with typed configuration, deterministic routing/localization, smoke tests, and dedicated mobile CI.

**Architecture:** Keep Flutter outside pnpm and preserve the feature-first boundary documented in `apps/mobile/README.md`. `app/` composes Riverpod providers, typed config, routing, and localization; presentation does not call raw HTTP/SQLite. Platform projects are generated by the pinned Flutter SDK instead of being handwritten.

**Tech Stack:** Flutter 3.47.3, Dart bundled with Flutter, flutter_riverpod 3.4.3, go_router 18.0.1, http 1.6.0, Flutter gen-l10n, GitHub Actions.

**Spec:** `docs/ADR/0002-mobile-flutter-bootstrap.md`

## Global Constraints

- Flutter SDK is pinned to `3.47.3` for this issue.
- Flutter remains outside `pnpm-workspace.yaml`; existing Node/core/backend CI is not weakened.
- No tide/lunar/drainage formulas are implemented in Flutter widgets.
- No direct SQL or raw HTTP calls from presentation widgets.
- Public API base URL is supplied by `CONNUOC_API_BASE_URL`; no credentials/admin tokens are represented in mobile config.
- Vietnamese (`vi`) is primary; English (`en`) is secondary.
- `flutter analyze`, `flutter test`, Android debug build, and iOS no-codesign build are required before merge.
- Dependency versions are exact in `pubspec.yaml`; `pubspec.lock` is committed.
