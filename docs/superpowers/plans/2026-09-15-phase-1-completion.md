# Phase 1 Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close Phase 1 with reproducible installs, independent lunar/tide reference validation, a real tide benchmark baseline, and a clean integration exit gate.

**Architecture:** Keep `shared-types`, `geo`, `lunar-calendar`, and `tide-engine` framework-independent and offline-capable. Reference fixtures are stored as immutable test data with provenance metadata; deterministic engine code consumes no network/database APIs. GitHub Actions is the authoritative clean-checkout verification environment.

**Tech Stack:** Node.js 24, pnpm 12.4.1, TypeScript 6.0.3, Vitest 5.0.0, ESLint 10.10.0.

**Spec:** `docs/ROADMAP.md` Phase 1, `docs/TODO.md` P0/P1 core sections, `docs/TIDE-ENGINE.md`, `docs/LUNAR-CALENDAR.md`, `docs/DATA-SOURCES.md`.

## Global Constraints

- Core calculation packages must run without network, database, NestJS, Flutter, browser, or filesystem dependencies in calculation paths.
- Timezone, unit, datum, phase convention, and provenance must never be inferred silently.
- Reference fixtures generated by the implementation under test are not valid independent golden truth.
- Tide reference data must carry source/license/datum/phase semantics.
- Lunar reference facts must be independently cross-checked and source URLs recorded.
- CI must run from a fresh checkout and fail on lint/type/test/build regressions.
